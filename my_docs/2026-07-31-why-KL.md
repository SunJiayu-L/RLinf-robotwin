## 一、问题背景：为什么 handover_block PPO 很难

`handover_block` 是整个任务集中 SFT 基线最低的任务（12.5%）。标准 PPO（v1 超参，kl_beta=0，lr=5e-6）直接训练后性能反而下降到 29.2%，低于训练前 eval baseline（37.5%），多次实验均失败。

失败原因分析：

1. **极度稀疏的奖励信号。** 训练初期 `success_once` 约 9%，即 91% 的轨迹奖励为 0。PPO 的策略梯度估计在奖励稀疏时方差极大，策略容易随机漂移。

2. **无正则化锚点。** 标准配置 `kl_beta=0`，训练时策略可以任意偏离 SFT 初始点。SFT 模型虽然成功率低，但已学到基本的抓取-传递动作结构；无约束的 PPO 容易把这些结构破坏。

3. **单任务策略泛化差。** SFT 模型在 20 个任务上协同训练，策略具有通用的动作先验。单独对 handover_block 做无约束 PPO 会过拟合到稀疏的成功信号，破坏其他任务的能力，且对 handover_block 自身也不一定有益。

---

## 二、核心思路：以多任务策略为参考锚点

我们有一个在 5-task（BBH + CA + CB + **HB** + MPA）联合训练的 PPO 策略（24 GPU，step 100 checkpoint），它：

- 在混合任务的奖励信号中见过 handover_block 的成功轨迹
- 相较 SFT 初始策略，对 handover_block 已有一定的任务适应
- 同时保留了其他任务的通用能力，不是对单一任务的过拟合

**设计思路：** 在 handover_block 单任务 PPO 训练时，以这个 5-task 联合策略 $\pi_{\text{ref}}$ 作为参考，在 loss 中加入一项"当前策略不要离参考策略太远"的惩罚。

这样训练能同时做到：
- 利用 PPO 的在线奖励信号，向 handover_block 的成功方向优化
- 通过 KL 约束，保持与 5-task 策略学到的有效动作结构的接近

## 三、目标函数

**标准 PPO actor loss：**

$$L_{\text{PPO}}(\theta) = -\mathbb{E}\left[\min\left(r_t(\theta)\hat{A}_t,\ \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\hat{A}_t\right)\right]$$

其中 $r_t(\theta) = \dfrac{\pi_\theta(a_t|s_t)}{\pi_{\text{old}}(a_t|s_t)}$ 为概率比。

**加入参考策略 KL 惩罚后的总 loss：**

$$\boxed{L_{\text{total}}(\theta) = L_{\text{PPO}}(\theta) + \beta_{\text{ref}} \cdot \widehat{D}_{\text{KL}}(\pi_\theta \| \pi_{\text{ref}})}$$

其中：
- $\beta_{\text{ref}}$（`ref_kl_beta`）：KL 惩罚系数，与官方 `kl_beta` 字段独立
- $\pi_{\text{ref}}$：5-task 联合 PPO step-100 checkpoint，训练全程冻结
- $\widehat{D}_{\text{KL}}$：用采样轨迹估计的 KL 散度（见下节）

## 四、KL 估计器的选择

### 4.1 为什么是"估计"而非精确 KL

精确的 KL 散度需要对整个动作空间积分：

$$D_{\text{KL}}(\pi_\theta \| \pi_{\text{ref}}) = \mathbb{E}_{a \sim \pi_\theta}\left[\log \pi_\theta(a|s) - \log \pi_{\text{ref}}(a|s)\right]$$

但在 PPO 的 training 阶段，动作样本来自 rollout 时的 **旧策略 $\pi_{\text{old}}$**，而非当前策略 $\pi_\theta$。因此只能做离策略近似估计（importance sampling 下的 Monte Carlo 估计）。PPO clip 约束保证了 $\pi_\theta$ 与 $\pi_{\text{old}}$ 足够接近，使得这个近似合理。

### 4.2 三种估计器

设 $r = \log \pi_{\text{ref}}(a|s) - \log \pi_\theta(a|s)$，即 ref 相对于 current 的 log-ratio。

| 估计器 | 公式 | 特点 |
|---|---|---|
| **k1**（`kl`） | $-r = \log\pi_\theta - \log\pi_{\text{ref}}$ | 最简单，可为负，方差大 |
| **k2**（`mse`） | $\frac{1}{2}r^2$ | 对称，方差低于 k1 |
| **k3**（`low_var_kl`） | $e^r - r - 1$ | **恒非负，方差最低**，与真实 KL 的泰勒展开一致 |

### 4.3 为什么选 k3（low_var_kl）

k3 是 John Schulman 在 [Approximating KL Divergence (2020)](http://joschu.net/blog/kl-approx.html) 中推荐的估计器：

$$\widehat{D}^{(k3)}_{\text{KL}}(\pi_\theta \| \pi_{\text{ref}}) = e^r - r - 1, \quad r = \log\pi_{\text{ref}} - \log\pi_\theta$$

**性质：**

1. **恒非负**（$e^r - r - 1 \geq 0$，因为 $e^x \geq x+1$），不会出现"KL 为负"的数值异常
2. **方差最低**，TRL、OpenRLHF 等主流 RLHF 框架均以此为默认
3. **泰勒展开与真实 KL 一致**：当 $r \approx 0$ 时，$e^r - r - 1 \approx \frac{1}{2}r^2 \approx D_{\text{KL}}$

**实现（`rlinf/algorithms/utils.py`）：**

```python
def kl_penalty(logprob, ref_logprob, kl_penalty):
    if kl_penalty in ("low_var_kl", "k3"):
        r = ref_logprob - logprob          # r = log π_ref - log π_current
        r = torch.clamp(r, min=-20, max=20)  # 数值稳定性
        ratio = torch.exp(r)
        kld = (ratio - r - 1).contiguous()
        return torch.clamp(kld, min=-10, max=10)
```

## 五、logprob 的计算：flow matching 模型的特殊性

本模型是 **Flow Matching（流匹配）模型**（π0.5 / pi05），不是 LLM，因此 logprob 不是离散 token 的 softmax，而是**连续去噪过程的高斯对数似然**。

### 5.1 流匹配策略的随机性来源

Flow Matching 在推断时有两种模式：

- **flow_ode（确定性）**：给定观测，动作唯一确定，$\sigma = 0$，无法计算 logprob
- **flow_sde（随机，训练用）**：去噪的每一步加入随机高斯噪声，$\sigma > 0$，才能定义 logprob

训练时必须使用 `flow_sde` 模式。

### 5.2 单步去噪的 logprob

模型预测速度场 $v_\theta(x_t, t)$，推算下一步的均值和方差：

$$\mu_t = \alpha \cdot x_{0,\text{pred}} + \beta \cdot x_{1,\text{pred}}, \quad \sigma_t = \sqrt{\Delta} \cdot \sigma_i$$

其中 $x_{0,\text{pred}} = x_t - v_\theta t$，$x_{1,\text{pred}} = x_t + v_\theta(1-t)$。

单步对数似然：

$$\log p(x_{t-1} | x_t, s) = \log \mathcal{N}(x_{t-1};\, \mu_t,\, \sigma_t^2 \mathbf{I}) = \sum_{d=1}^{D} \left[-\frac{1}{2}\log(2\pi\sigma_t^2) - \frac{(x_{t-1}^d - \mu_t^d)^2}{2\sigma_t^2}\right]$$

shape 为 `[bsz, action_chunk=50, action_dim=14]`。

### 5.3 多去噪步的聚合

去噪过程共 `num_steps`（默认 5）步，训练时对各步 logprob 取均值（Monte Carlo 估计全程对数似然）：

$$\log \pi_\theta(\mathbf{a}|s) \approx \frac{1}{K} \sum_{k=1}^{K} \log p(x_{t_{k}-1} | x_{t_k}, s)$$

### 5.4 chunk-level 聚合（handover_block 配置）

PPO ratio 需要标量 logprob。按 `logprob_type: chunk_level` 对所有维度求和：

$$\log \pi_\theta(\mathbf{a}|s) = \sum_{\text{chunk}} \sum_{\text{dim}} \log p \quad \in \mathbb{R}$$

shape：`[bsz, 50, 14]` → `[bsz]`（sum over dim=[1,2]）

这里的 `bsz` 是**展平后的 action chunk 样本数**，不是 episode 数（一个 episode 在 rollout 阶段展平为多个模型调用样本）。

## 六、ref_logprobs 的计算方式

### 6.1 参考权重管理

参考策略权重在 worker 初始化时从外部文件加载到 **CPU**，训练全程不更新：

```python
# fsdp_actor_worker.py — init_worker
ref_policy_path = self.cfg.algorithm.get("ref_policy_path", None)
if ref_policy_path is not None:
    self.ref_policy_state_dict = torch.load(ref_policy_path, map_location="cpu")
    self.offload_model_buffer = {}
    # 立即校验 key 与当前模型一致（避免 cpu_weight_swap 时崩溃）
    assert set(self.model.state_dict().keys()) == set(self.ref_policy_state_dict.keys())
```

### 6.2 每次 mini-batch 的 reference forward

训练时，每个 mini-batch 在正式 training forward **之前**，临时把参考权重换入 GPU，做一次 `no_grad` 前向，得到 `ref_logprobs`，然后立即换回训练权重：

```python
# fsdp_actor_worker.py — run_training
ref_logprobs_raw = None
if self.ref_policy_state_dict is not None:
    with torch.no_grad():
        with self.amp_context:
            with cpu_weight_swap(self.model, self.ref_policy_state_dict, self.offload_model_buffer):
                _ref_out = self.model(forward_inputs=forward_inputs,
                                      compute_logprobs=True,
                                      compute_entropy=False,
                                      compute_values=False)
        ref_logprobs_raw = _ref_out["logprobs"].detach().float()
```

`cpu_weight_swap` 是一个 context manager：进入时把训练权重转出到 CPU、把参考权重载入 GPU；退出时还原。整个过程在同一个模型实例上完成，无需额外显存分配。

### 6.3 与官方实现的差异

官方 reasoning 路径在 **rollout 阶段**算 ref_logprobs（利用 disaggregated 流水线，ref forward 不额外占训练时间）。Embodied 路径没有这个流水线，因此在 **training 阶段**每个 mini-batch 即时计算，实现更简单但略增训练时间。

## 七、ref_kl_beta 与 kl_beta 的字段分离

官方 RLinf 已有 `algorithm.kl_beta` 字段，用于 reasoning/agent 路径的 KL 约束（参考策略为训练起始快照）。为避免与本实现冲突，新增独立字段：

| 字段 | 用途 | 默认值 |
|---|---|---|
| `algorithm.kl_beta` | 官方路径（reasoning/LLM），不动 | 0.0 |
| `algorithm.ref_kl_beta` | 本实现（embodied，外部参考策略） | 0.0 |
| `algorithm.ref_policy_path` | 参考策略 `.pt` 文件路径 | null |

三种运行模式：

| `ref_policy_path` | `ref_kl_beta` | 效果 |
|---|---|---|
| 未设置 | 任意 | 完全跳过，零额外开销 |
| 已设置 | `0.0` | 运行 ref forward，**仅监控** `actor/ref_kl_loss`，不影响 loss |
| 已设置 | `> 0` | 运行 ref forward，监控 + **加入 loss** |

`ref_kl_beta: 0.0` 的纯监控模式用于实验前确认 KL 量级（Phase 1），避免盲目设定系数。

## 八、完整 loss 公式汇总

设当前策略 $\pi_\theta$，旧策略 $\pi_\text{old}$（rollout 时），参考策略 $\pi_\text{ref}$（5-task PPO step-100，冻结），对于一个 action chunk 样本 $(s, \mathbf{a})$：

$$r(\theta) = \frac{\pi_\theta(\mathbf{a}|s)}{\pi_\text{old}(\mathbf{a}|s)} = \exp(\log\pi_\theta - \log\pi_\text{old})$$

$$L_\text{CLIP}(\theta) = -\min\!\left(r(\theta)\hat{A},\ \text{clip}(r(\theta), 1-\epsilon, 1+\epsilon)\hat{A}\right)$$

$$L_\text{value}(\theta) = \text{HuberLoss}\!\left(V_\theta(s),\ V_\text{target}\right)$$

$$\rho = \log\pi_\text{ref}(\mathbf{a}|s) - \log\pi_\theta(\mathbf{a}|s)$$

$$\widehat{D}_\text{KL}(\pi_\theta \| \pi_\text{ref}) = e^\rho - \rho - 1 \quad \text{(k3 estimator)}$$

$$\boxed{L_\text{total}(\theta) = L_\text{CLIP}(\theta) + \alpha_v \cdot L_\text{value}(\theta) + \beta_\text{ref} \cdot \widehat{D}_\text{KL}(\pi_\theta \| \pi_\text{ref})}$$

所有项均对 mini-batch 内所有样本取均值（`loss_agg_func = token-mean`，按 `loss_mask` 加权）。

## 九、为什么选 5-task joint PPO step-100 作为参考

1. **step-100 处于有效学习区间。** 在 5-task eval 中，step-100 的 handover_block 成功率高于 SFT baseline，说明策略已经朝正确方向走了一段；但不像更晚的 step 可能对其他任务产生过拟合。

2. **多任务协同避免单任务过拟合。** 5-task 联合训练时，handover_block 的奖励信号与其他 4 个任务共同约束策略更新，学到的动作先验更鲁棒。

3. **与训练起点（SFT）正交互补。** SFT moe_sft20k 是 HB 的训练起点，而 5-task PPO step-100 是在 SFT 之后通过 RL 继续提升的策略。以后者为参考，等于把"RL 学到的有益成分"作为引导方向，而非仅仅约束不偏离 SFT。
